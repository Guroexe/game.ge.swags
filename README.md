# GEN.SWAGS

Браузерный FPS на Three.js (ES-модули, статический клиент без сборки).
Полностью офлайн: three.js лежит в `vendor/three/`, шрифты — в `assets/fonts/`,
внешние CDN не нужны — игру можно раздавать по локальной сети на iPhone.

## Деплой в интернет (GitHub + Railway)

Игра умеет работать одним процессом: тот же порт отдаёт статику и MP-WebSocket.
Railway даёт HTTPS из коробки — гироскоп iOS работает без самоподписанных сертификатов.

1. Залейте папку в GitHub:
   ```bash
   git init
   git add .
   git commit -m "gen.swags"
   git branch -M main
   git remote add origin https://github.com/<you>/gen.swags.git
   git push -u origin main
   ```
2. На [railway.app](https://railway.app): **New Project → Deploy from GitHub repo** → выберите репозиторий.
3. Railway сам выполнит `npm install` и `npm start` (`server/start.railway.js` — слушает `env PORT`).
4. В настройках сервиса включите **Generate Domain** — получите `https://<app>.up.railway.app`.
5. Откройте этот адрес с ПК и iPhone: мультиплеер подключится автоматически
   (`wss://` на тот же домен, поле сервера в меню можно оставить пустым),
   гироскоп — сразу, т.к. контекст уже secure.

Локальная разработка по-прежнему: `start.bat` / `node server/start.js` (HTTP :8080 + HTTPS :8343 + WS :7777).

## Запуск одним кликом (ПК + iPhone)


**`start.bat`** (Windows) — один процесс: статика `:8080` + MP-сервер `:7777`,
в консоли печатаются обе ссылки (для ПК и для iPhone в той же Wi-Fi сети).
Node берётся из PATH либо из рантайма kimi-desktop; зависимость `ws` уже
лежит в `server/node_modules/` — `npm i` не нужен.

```bash
node server/start.js          # то же самое без .bat
STATIC_PORT=9000 node server/start.js   # другой порт статики
```

## Запуск клиента (соло, вручную)

Откройте `index.html` через любой статический сервер, например:

```bash
npx serve .        # или python3 -m http.server
```

Соло-режим работает без сервера.

## Запуск сервера (мультиплеер, вручную)

Сервер — Node.js WebSocket (зависимость: только `ws`).

```bash
cd server
npm i
npm start            # порт 7777
PORT=8888 npm start  # другой порт через env
```

Без `?server=` и без подключения из меню — полноценная соло-игра (graceful fallback при любой сетевой ошибке).

### Подключение с ПК

1. Запустите сервер (см. выше) и статику (`npx serve .`).
2. Откройте игру → **МУЛЬТИПЛЕЕР** → введите ник, адрес `ws://localhost:7777` → **ПОДКЛЮЧИТЬСЯ**.
3. Выберите комнату из списка (кнопка ОБНОВИТЬ) или создайте свою → в лобби жмите **ГОТОВ**. Когда все игроки готовы — матч стартует автоматически.
4. Вкладка **ДРУЗЬЯ**: добавление по нику, входящие заявки (принять/отклонить), онлайн-статус, удаление.
5. Либо авто-подключение при загрузке через параметр URL:

```
http://localhost:8080/index.html?server=ws://localhost:7777
```

### Подключение с iPhone (одна Wi-Fi сеть)

1. Узнайте IP компьютера в локальной сети (`ipconfig getifaddr en0` на macOS, `ip addr` на Linux).
2. Запустите на компьютере сервер (`npm start`, слушает на `0.0.0.0:7777`) и статику; откройте порт 7777 в брандмауэре.
3. На iPhone откройте:

```
http://<IP-ПК>:8080/index.html?server=ws://<IP-ПК>:7777
```

(или введите `ws://<IP-ПК>:7777` вручную на экране МУЛЬТИПЛЕЕР).

> Примечание: голосовой чат (`getUserMedia`) браузеры разрешают только в secure context — `localhost` или `https://`. По `http://<IP>` микрофон будет недоступен (остальной мультиплеер работает).

### Гироскоп на iPhone — нужен HTTPS

iOS Safari отдаёт датчики движения **только по HTTPS** (по `http://` они молча заблокированы). Для гироскопа:

```bash
python serve_https.py        # порт 8343, сертификат из dev/certs/
```

На iPhone откройте `https://<IP-ПК>:8343`, примите предупреждение сертификата
(«Подробности → Перейти на сайт» — сертификат самоподписанный, ваш локальный),
затем Настройки → ГИРОСКОП → включите → «Разрешить». Если разрешение было
дано ранее — кнопка «ИГРАТЬ» сама дозапросит его при старте матча.
Если сертификата нет — `serve_https.py` создаст его сам (нужен openssl в PATH).

### Мультиплеер в матче

Сервер авторитетен: HP/попадания/смерти/респавны, кеш-режим (подбор/станции/счёт), разрушение чанков по `chunkId` (идемпотентно). Удалённые игроки рендерятся той же аниме-девушкой, что и боты (командные варианты волос/свечения/глаз, имя+HP спрайт, интерполяция 100 мс). Локальная логика режима cashout в MP отключена — клиент только зеркалит серверное состояние (`js/game/mp.js`: `RemotePlayers`, `MPCashMirror`).

- **Чат**: `T` — общий, `Y` — командный, лента в левом нижнем углу HUD; на тачах — кнопка ЧАТ. Лимит 4 сообщ/сек.
- **Голос**: кнопка 🎤 в лобби и в матче (OFF → ON → MUTE), `getUserMedia` запрашивается только по кнопке; индикатор говорящего 🔊 у тиммейтов и в лобби.

### Возможности сервера

- **Лобби**: регистрация ника, список комнат, создание/вход (дефолтная `HUB_1`, до 9 игроков, 3 команды × 3, автораспределение в самую малочисленную), готовность, автостарт.
- **Авторитетный матч 20 Гц**: lerp-ретрансляция позиций (клиент шлёт 15 Гц), валидация попаданий по дистанции, HP/смерти/респавны (3 с), кеш-режим (кешбокс, кешаут-станции 5 с, счёт команд), идемпотентное разрушение чанков.
- **Чат**: общий лобби-чат, комнатный и командный чат в матче; лимит 200 символов и 4 сообщ/сек.
- **Друзья**: add/accept/decline/remove по нику, онлайн-статус, персист в `server/data/friends.json` (атомарная запись tmp+rename).
- **Голосовой чат**: WebRTC signaling (offer/answer/ice) mesh внутри команды; медиа — P2P, сервер только ретранслирует сигналы.
- **Надёжность**: анти-флуд, heartbeat ping/pong с чисткой мёртвых соединений, graceful shutdown (SIGINT/SIGTERM сохраняет данные).

## Гироскоп на iPhone

Прицеливание поворотом устройства (AR-окно: повернул телефон — повернулась камера).
Реализация — `js/engine/gyro.js` (`GyroController`), диагностика — `js/game/gyrodebug.js`.

### Отклик: сенсорный фьюжн с приоритетом скорости

Задержка сведена к минимуму двухканальной схемой (источник виден в оверлее как
`FUSION` / `DEVICEORIENTATION` / `DEVICEMOTION`):

- **Быстрый канал — `devicemotion.rotationRate`**: угловые скорости (deg/s)
  интегрируются в дельту кватерниона **в каждом событии** (dt по `event.timeStamp`),
  выходное состояние обновляется сразу в обработчике — отклик в то же событие,
  0 кадров задержки; rAF (`applyToCamera`) только читает готовое состояние.
  Конвенция интеграции (beta→x, gamma→y, alpha→z, body-frame) верифицирована
  численно против three.js: 0° расхождения за 5 с сложного движения @100 Гц.
- **Медленный канал — `deviceorientation`** (абсолютная поза): только анти-дрейф
  коррекция интегрированной позы — комплиментарный фильтр с малым k=0.05
  («подтягивание» не ощущается; разнос >30° — мгновенный snap). Если motion-канал
  молчит, orientation становится первичным (прямое следование).
- **ОТКЛИК** (слайдер в настройках, МГНОВЕННЫЙ ↔ ПЛАВНЫЙ, 0..1, дефолт 0.15):
  EMA с alpha ≈ 1 − 0.85·response при 60 Гц (дефолт ≈ 0.87 — почти сырой),
  frame-rate independent. Персистится в localStorage.
- **ФИЛЬТР ШУМА (DEAD-ZONE)** — по умолчанию ВЫКЛ (0); включайте только при
  заметном дрожании прицела в покое (шумный датчик).

### Гироскоп + палец ОДНОВРЕМЕННО

Подавления тачем **нет**: дельты гироскопа и тач-обзора аддитивно суммируются в
общий аккумулятор `player.look` (yaw/pitch). Палец не сбрасывает калибровку
гироскопа; после отпускания гироскоп просто продолжает с текущей позы устройства —
никакого «догона» и рывков.

   `DeviceOrientationEvent.requestPermission()` (+ `DeviceMotionEvent` для фьюжна) —
   подтвердите «Разрешить». Если отказали — кнопка предложит повторить; либо
   **Настройки iPhone → Safari → Движение и ориентация** (или «Настройки сайта» в Safari).
3. Строка **СТАТУС** в настройках честно показывает состояние:
   `АКТИВЕН · N Гц · FUSION`, `НУЖНО РАЗРЕШЕНИЕ iOS`, `ОТКАЗАНО`, `ДАТЧИК НЕДОСТУПЕН` и т.д.

### Калибровка

- **КАЛИБРОВКА** (в настройках или в оверлее) — текущая поза устройства становится нулём обзора.
- Калибровка также выполняется автоматически при старте матча (на тач-устройствах).
- **АНТИ-ДРЕЙФ** (опционально): при неподвижном удержании >2 с ноль медленно
  подтягивается к текущей позе — компенсирует дрейф датчика. Работает только в
  покое, латентность не добавляет.

### Что под капотом (защита от iOS-ловушек)

- **Quaternion-маппинг** (подход `DeviceOrientationControls`): мировые yaw/pitch
  извлекаются из относительного поворота `qEst·q(t0)⁻¹`, поэтому поворот экрана
  portrait/landscape **не ломает оси** (никаких ручных перестановок alpha/gamma).
- `alpha === null` (десктоп/нет датчика) → статус «ДАТЧИК НЕДОСТУПЕН», а не молчаливый ноль.
- Dead-zone с накоплением (по запросу), EMA-отклик, unwrap углов.
- `enable()` идемпотентен — повторные включения не плодят listeners.
- Fallback: если `deviceorientation` недоступен/молчит, обзор работает по чистой
  интеграции `rotationRate`; мировая вертикаль выравнивается по гравитации
  (`accelerationIncludingGravity`), если она есть в событии.

### Диагностика (что видеть на устройстве)

- Кнопка **ТЕСТ ГИРОСКОПА** в настройках или параметр URL `?gyrodebug=1` —
  полупрозрачный оверлей поверх игры: статус, разрешение, **источник**
  (FUSION/DEVICEORIENTATION/DEVICEMOTION + ошибка фьюжна), live alpha/beta/gamma,
  применяемые yaw/pitch, частота событий (Гц), **ЛАТЕНТНОСТЬ** (мс от последнего
  события датчика до применения к камере), FPS, кнопка калибровки.
  Поверните устройство — числа должны меняться, СОБЫТИЯ ≈ 60 Гц,
  ЛАТЕНТНОСТЬ < 30 мс, ИСТОЧНИК = FUSION.
- `?gyrotest=1` — браузерный самотест: синтетические `deviceorientation` +
  `devicemotion` диспатчатся в работающую игру: камера реагирует **в том же
  rAF-тике**, тач-дельта и гиро-дельта складываются, `camera.rotation` следует
  за `look` (результат PASS/FAIL на экране и в консоли).

### Что уже проверено

- **Логические тесты** (`node test/gyro.test.mjs`, 67 проверок): кватернионная
  математика сверена с three.js (включая интеграцию угловой скорости и
  shortest-arc); калибровка → поворот 90° → ожидаемый yaw; invert X/Y;
  отклик (response=0 — полный поворот за 1 кадр; сходимость дефолта); sens ×2;
  null-alpha → no-data; enable×3 → 1 listener; landscape-маппинг;
  **тач+гиро параллельно (аддитивность, отсутствие рывка после отпускания)**;
  dead-zone выкл/вкл; анти-дрейф; permission granted/denied/error/retry;
  motion-fallback (в т.ч. выравнивание по гравитации); **латентность —
  rotationRate меняет выход в том же тике (0 кадров)**; фьюжн-коррекция
  ограничивает дрейф интеграции (k=0.05 → <4° при дрейфе 4.5°/с, k=0 → >12°);
  без двойной обработки; переход motion→fusion без рывка.
  Тесты подавления тачем (suppress 250 мс) **удалены** — механика убрана.
- **Браузерная эмуляция** (`?gyrotest=1`): камера реагирует на синтетические
  события немедленно, тач+гиро складываются, `camera.rotation` следует за `look`.

### Чек-лист проверки на iPhone (ручной)

1. Открыть `?gyrodebug=1`: СТАТУС = `НУЖНО РАЗРЕШЕНИЕ iOS` → включить ГИРОСКОП →
   системный диалог → «Разрешить» → СТАТУС = `АКТИВЕН · ~60 Гц`, ИСТОЧНИК = FUSION.
2. Повернуть телефон влево/вправо: прицел идёт **сразу** (ЛАТЕНТНОСТЬ < 30 мс),
   YAW растёт без заметной инерции (если зеркально — ИНВЕРСИЯ X; наклон — PITCH/ИНВЕРСИЯ Y).
3. Слайдер **ОТКЛИК**: влево (МГНОВЕННЫЙ) — прицел один-в-один за телефоном;
   вправо (ПЛАВНЫЙ) — мягкое догоняющее движение. Вернуть в ~15%.
4. Нажать КАЛИБРОВКА в удобной позе: обзор замирает без смещения; увести телефон
   и вернуть — прицел возвращается к той же точке.
5. **Одновременно** водить обзор пальцем (правая половина экрана) и поворачивать
   телефон: движения складываются, гироскоп не глохнет; отпустить палец —
   никакого рывка/догона, гироскоп продолжает с текущей позы.
6. Повернуть экран (portrait/landscape) и повторить п.2: оси не «перепутаны»;
   подержать телефон неподвижно 5 с с включённым АНТИ-ДРЕЙФ — прицел не ползёт.
   Если прицел дрожит в покое — включить ФИЛЬТР ШУМА (DEAD-ZONE).
